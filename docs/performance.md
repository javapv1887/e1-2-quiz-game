# 퀴즈가 1,000개 이상일 때의 성능

`N`은 문제 수, `B`는 문제와 선택지를 담은 JSON의 바이트 수, `T`는 모든 제목의 문자 수입니다. 선택지는 문제당 4개입니다. 질문과 선택지 길이가 비슷하면 `B`와 `T`도 대체로 `N`에 비례합니다.

| 작업 | 시간 | 추가 메모리와 입출력 |
| --- | --- | --- |
| 시작 시 읽기·검증 | O(B + N) | JSON 파싱 결과와 `Quiz` 객체가 한동안 함께 있어 O(B + N) |
| 랜덤 출제 준비 | O(N) | 퀴즈 객체의 참조만 복사해 O(N) |
| 퀴즈 추가·최고 기록 저장 | O(B + N) | 이전 파일을 검증하고 백업과 새 상태를 각각 씁니다. 저장 중 O(B + N) 메모리가 필요하고, 디스크에는 정상본과 백업 외에 교체용 임시 파일이 잠시 생깁니다. |
| 목록 출력 | O(T + N) | 각 제목을 한 줄씩 출력해 출력 문자열을 한꺼번에 보관할 필요가 없습니다. |
| 제목 부분 검색을 추가할 경우 | 고정 검색어의 전체 순회는 O(T + N) | 일치 항목 수가 `K`라면 결과 목록에 O(K). 현재 게임에 검색 메뉴는 없습니다. |

## 로컬 측정

Python 3.14.3, Apple Silicon Mac에서 짧은 한국어 제목과 선택지 4개를 가진 합성 퀴즈를 사용했습니다. 시간은 작업별 7회 중앙값입니다. 저장은 최고 기록을 매번 바꿔 기존 파일 검증과 백업·본 파일 쓰기를 포함했습니다. 검색은 찾는 제목이 없는 고정 문자열로 모든 제목을 확인했습니다. 메모리는 시작 시 JSON 읽기·검증 구간의 `tracemalloc` 최대 Python 할당량입니다.

| 퀴즈 수 | JSON 크기 | 읽기·검증 | 백업 포함 저장 | 복사·셔플 | 제목 전체 검색 | 읽기 최대 메모리 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 203.1 KiB | 2.384 ms | 18.551 ms | 0.174 ms | 0.031 ms | 1.02 MiB |
| 10,000 | 2,040.0 KiB | 19.675 ms | 156.299 ms | 1.754 ms | 0.287 ms | 9.25 MiB |

이 수치에는 콘솔 출력, 사람의 입력 시간, 운영체제의 전체 메모리 사용량이 포함되지 않습니다. 디스크·파일 캐시·문자열 길이에 따라 측정값이 달라집니다.

## 병목에 따른 개선 방안

- 문제 목록이 길어지면 먼저 페이지 단위로 출력하고 게임당 문제 수를 선택하게 합니다. 이미 메모리에 있는 목록에서 일부만 무작위로 출제할 때는 `random.sample()`로 필요한 수만 뽑을 수 있습니다.
- 퀴즈 추가나 점수 갱신 때 전체 JSON 재작성이 느려지면 표준 라이브러리의 SQLite로 옮겨 문제와 최고 점수를 행 단위로 저장합니다. 퀴즈 변경과 관련 점수 갱신을 한 트랜잭션에 묶고, 기존 JSON을 가져온 뒤 복구 방법을 검증합니다.
- 정확한 제목 검색이 많이 필요하면 제목을 정규화해 SQLite 제목 인덱스를 사용합니다. 임의 부분 문자열 검색이 필요하면 일반 제목 인덱스로 해결하기 어려우므로 검색 방식과 데이터 규모를 확인한 뒤 FTS5의 토크나이저나 별도 검색 인덱스를 검토합니다.
